MMMerge 한국어 런타임 현지화 점검 기록 — v1.0.10 TEST
========================================================

확인된 원인
- 한국어 번역 레코드는 존재했지만 Merge가 GameInitialized2에서 영어 값을 Lua 테이블과 포인터 캐시에 복사했습니다.
- 이후 원본 Game 테이블만 한글화되어도 MapNews, ContinentNews, ProfessionNews, TownPortalControls.Sets 같은 복사본은 영어로 남았습니다.
- NPCNews의 주제는 별도 Game.NPCTopic 항목이 아니라 각 NPCNews 본문 바로 뒤에 저장된 두 번째 문자열입니다. 이를 일반 NPCTopic으로 처리한 기존 방식은 잘못되었습니다.

정적 번역 범위 점검
- KO_NPCNews.txt: 921개, ID 0~920, 누락 0, 중복 0
- KO_NPCNewsTopics.txt: 921개, ID 0~920, 누락 0, 중복 0
- NPCNews 본문/주제 ID 집합 일치
- KO_NPCText.txt: 2,713개, ID 1~2713, 누락 0, 중복 0
- KO_NPCTopic.txt: 1,794개, ID 1~1794, 누락 0, 중복 0
- KO_NPCGreet1.txt: 332개, ID 0~331, 누락 0, 중복 0
- KO_NPCGreet2.txt: 332개, ID 0~331, 누락 0, 중복 0
- 전체 일반 KO_*.txt 대상 중복 0

재적용 및 검사 대상
- Game.MapNews
- Game.ContinentNews
- Game.ProfessionNews
- Game.NPCProfessions
- Game.NPCPersonalities
- TownPortalControls.Sets
- vars.RndNPCPersist
- 동적으로 배치된 활성 Game.NPCTopic
- DrawNPCGreeting 최종 문자열
- GetTransitionText의 Text/CustomText

안전 조치
- NPCNews와 NPCNewsTopics는 조기 적용에서 제외합니다. Merge가 원문 행의 본문/주제 경계를 읽은 뒤 후기 단계에서 적용합니다.
- 동일한 영문 문자열이 문맥에 따라 서로 다른 한국어로 번역된 경우 자동 캐시 치환을 하지 않습니다.
- 새 게임 초기화 중 Game.NPC 메모리는 읽지 않으며 LoadMapScripts 이후에만 저장된 NPC 이름을 보정합니다.

검증 범위의 한계
- 맵 Lua 스크립트에 번역 테이블 없이 직접 작성된 영문 문장은 자동으로 번역할 수 없습니다.
- 글꼴 누락, 화면 잘림, 실제 클릭 흐름은 게임 내 시험이 필요합니다.
